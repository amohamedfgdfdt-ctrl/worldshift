# Phase 2 improvements report

## Implemented and verified
- Graphics settings system with 4 presets + Custom, 16 independent settings, capability gating, LocalStorage persistence, live preview/Apply/Cancel/Restore Defaults/Auto Detect (see GRAPHICS.md).
- Render pipeline: direct path or HDR composer (MSAA 4×, FXAA, SMAA, GTAO, bloom, grade, light shafts).
- Performance engine: FPS, frame time, worst frame, CPU render time, optional GPU timer (EXT_disjoint_timer_query_webgl2), frame-time graph, dynamic resolution, Auto Graphics Mode, rAF frame limiter, refresh-rate probe.
- Atmosphere: height fog + sun scatter by overriding three.js fog chunks.
- Water: 4 visual tiers, wave sum, decaying visual foam (driven by speed and depth gradients, so obstacles and drops produce foam), caustics, planar reflection. **The flow simulation is unchanged and independent: after 300 steps the water state checksum is identical at water quality 0 and 3 (tested).**
- Terrain: detail layers + micro normal strength by level. Vegetation: oak, birch, pine, bush, rock, grass, flower, reed; two-level distance LOD for trees (round-robin, hysteresis); GPU distance culling; density by fraction.
- Particles: pooled factory smoke and motes/fireflies.
- GLB/glTF pipeline with multi-material models (tested).

## Tests (Chrome + SwiftShader software GL, 640×400, no real GPU or phone was available)
- Per preset (low/medium/high/ultra): build 3–5 types, delete, add water (volume increases, no NaN, flow >0), camera rotate/zoom, save → clear → load (counts match), 9 live setting changes during play, viewport resize: **32/32 checks passed, 0 page errors** (`tests/gfx8.py`).
- Memory: 4 full cycles through all presets: geometries 27, textures 27 and program count (56) stable after cycle 2 – no leak.
- Auto mode: on slow software GL it lowered resolution to 50 % then stepped Ultra → High → Medium → Low. The *restore* path is implemented but could not be exercised because the software renderer never reached headroom.
- Phase 1 simulation tests still pass.

## Measured comparison (software GL, 278 buildings placed, NOT representative of real devices)
| Preset | ms/frame | draw calls | triangles | render mode |
|---|---|---|---|---|
| Low (75 % scale) | 87 | 21 | 267k | direct |
| Medium | 213 | 30 | 474k | composer + FXAA |
| High | 327 | 54 | 653k | composer + SMAA + bloom |
| Ultra | 1137 | 100 | 1.46M | MSAA + GTAO + planar reflection + 4096 shadows |

The ordering and the relative cost are meaningful; absolute numbers are not. Ultra is intentionally expensive (extra scene passes for reflection and AO); Auto Detect and Auto mode exist to keep it away from devices that cannot afford it.

## Problems found and fixed during testing
- Default three.js FXAA smeared foliage: sub-pixel blending reduced in the vendored copy.
- Fog looked much heavier on the post-processing path (three applies built-in fog after tone mapping on the direct path, before it on the composer path): density compensated (×0.6), matching mean colour within ~7/255.
- First-run benchmark could overwrite settings changed by the user in the first seconds: now skipped if values changed.
- `gl.finish()` is not a reliable timing fence: the benchmark measures throughput over animation frames instead.

## Honest limitations
- "Refraction" is approximate (bed distortion is not done; depth colouring + caustics only); no screen-space refraction.
- Planar reflection covers the lake level only; rivers use sky reflection.
- No PBR terrain texture arrays yet (terrain uses vertex colours + procedural detail layers); no triplanar rock; terrain grid fixed at 128².
- Clouds are still the 2D procedural sky clouds; no volumetric clouds. Light shafts are a screen-space approximation.
- Vegetation has no alpha leaf cards or fir/fern species; LOD exists only for oak/pine/birch. GLB LODs, KTX2/Draco not supported.
- Not tested on real phones or GPUs; GPU timing and 90/120 FPS paths could not be verified here.
- Texture quality changes filtering only; procedural texture resolution is fixed.

# Asset pipeline upgrade (follow-up)

## Review of the previous pipeline (problems found)
1. It kept only the **first material of every mesh**: a mesh with several materials (material array + geometry groups) silently lost all but one.
2. It replaced **buildings only**; trees, shrubs, rocks and plants could not be replaced.
3. No LOD, no compression support, no validation, no per-asset metadata.

## Now supported (all verified by `tests/assets1.py`, 30/30 checks, real GLB files generated by three's GLTFExporter at test time and loaded through the real code path)
- **Targets:** every building type, oak / pine / birch / player tree, bush, reed, rock, grass, flower.
- **True multi-material:** one mesh with several materials is split by geometry group; per-material buckets are merged into one geometry with one group per material (7 materials / 244 triangles in, 7 groups / 244 triangles out; albedo, normal, roughness, AO + uv1, alpha-test and double-sided kept).
- **LOD High / Medium / Low** for external assets via `LodInstanceSet` (distance switching with hysteresis, round-robin updates, per-level shadow casting). Verified: far camera → all low, camera at an instance → high; delete/pick/save-load work while instances sit in lower levels.
- **Manifest v2** (category, target, dimensions, fit, scale, yOffset, per-level url + distance) with validation (6 kinds of invalid entry rejected in the test), v1 `models` map still accepted.
- **Automatic procedural fallback:** missing file, corrupt file, invalid entry → procedural model untouched (tested); a broken lower LOD is dropped with a warning; empty/missing manifest loads nothing and never imports the glTF loader.
- **Compression:** Draco verified with a real encode→GLB→decode round trip; Meshopt and KTX2/Basis decoders initialise but have not decoded a real file here; decoders (0.8 MB) are lazy and optional.
- **Unchanged:** water simulation, building/save systems (only a pick/replace hook was added to BuildingSystem; serialize→clear→load re-verified), graphics settings (shadows, density, draw distance, texture quality, presets all still drive GLB assets; gfx8 still 32/32).

## Still needs work
- No real final assets exist yet (none were invented): everything on screen is still procedural until models are supplied (`ASSETS_TODO.md`).
- Meshopt and KTX2 not exercised with real compressed files (no encoder offline); GLB animations/skins unsupported; one material set per target (no per-instance material variants beyond the colour tint).
- Wind sway is vertex-height based (works for trees/shrubs, not authored vertex-colour wind masks).
- LOD uses distance only (no screen-size metric), and no cross-fade between levels.
- Foundations for buildings on slopes and the building footprint are still the game's; models are not auto-fitted to the footprint unless `fit` is set.
- Still no real-device testing.
